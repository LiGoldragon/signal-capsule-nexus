# Upgrades

## 0.5.0 — 1.0.0 through 3.0.0 renumbered to the 0.x line

A breaking change on a 0.x crate takes the next minor, so the contract published as 1.0.0, 1.0.1,
2.0.0 and 3.0.0 is renumbered 0.5.0. The contract, its archive and its Datom text are those of
3.0.0 (c019498); only the version moves. 1.x, 2.x and 3.x were never deployed and leave the build
base's registry. A consumer pins 0.5.0 at its new commit in place of 3.0.0.

## 3.0.0 — a subscription carries each pane whole

`Subscribe.Session` is answered by `Subscribed.Stream<Panes Known>`: a change is the pane whole, its label and attempt with its state, so a label given at Start reaches every open stream. The type `Changed` is gone; `Output::Subscribed` carries `signal::Frame<Panes, Known>`, and `Answering::subscribe` and `Answer::Subscribed` carry `signal::Stream<Panes, Known>`.

- `Panes` bears `signal::Following` with `type Change = Known`: the Known given replaces the pane held, or is taken in when the pane is not held; a Known whose state is Dead takes the pane out, so Dead is told once.
- The archive of `Output` changes, so a peer built on 2.x cannot read a 3.0.0 Output. The Datom text of a change is a Known: `Subscribed.Changed.{ { main wQ:pT } Some.designer Idle Settled }`, where it was `Subscribed.Changed.{ { main wQ:pT } Idle }`.

The pins stay: signal 11.2.0 (4f5cbb9), datom-codec 09a0526, protos c93b598. To deploy: publish each moved pane as its Known, and fold `Frame::Changed(known)` with `Panes::after`.

## 2.0.0 — Subscribe is answered by a stream

`Subscribe.Session` is answered by `Subscribed.Stream<Panes Changed>`: one subscription of the session, its frames each one `Output::Subscribed(signal::Frame<Panes, Changed>)`. `Opened` comes first and once, with the panes the Capsule holds in the session that are not Dead; `Changed` carries each change; `Lagged` carries the panes anew to a subscriber that fell behind, which goes on from them. A refused Subscribe is answered once, `SubscribeRefused.Outcome`.

- `Changed.{ Pane State }` is a type, no longer an output; its generated struct is `Changed`, where it was `Changed_Data`. `Output::Changed` is gone.
- `Panes.Vector<Known>` is the subscription's state, and it bears `signal::Following` here, written by hand: a change whose state is Dead removes its pane, so Dead is told once and a later `Opened` holds no dead pane; any other state replaces the pane's own, and a pane not yet held is taken in with no label and its attempt settled.
- `Answering::subscribe` yields `signal::Stream<Panes, Changed>` or the refusal, and `Answerable`'s `Answer` is the generated `Answer`: `Once(Output)` for every input answered once, `Subscribed(signal::Stream<Panes, Changed>)` for Subscribe.
- The archive of `Output` changes, so a peer built on 1.x cannot read a 2.0.0 Output; the Datom text of a subscription is its frames, `Subscribed.Opened.[ … ]`, `Subscribed.Changed.{ { main wQ:pT } Idle }`, `Subscribed.Lagged.[ … ]`.

The pins stay: signal 11.2.0 (4f5cbb9), datom-codec 09a0526, protos c93b598. To deploy: answer Subscribe with the stream, read each frame from `Output::Subscribed`, and write `Changed` where it was `Changed_Data`.

## 1.0.1 — signal 11.2.0

Only the signal pin moves: signal 11.2.0 (4f5cbb9), which adds `signal::Following` and changes no type, archive or digest this contract has. A consumer repins signal with it, so `links = "signal"` finds one package in its graph.

## 1.0.0 — ethos-zero 30.0.0, signal 11.1.0

The contract is regenerated by ethos-zero 30.0.0 (b97d952) and signal moves to 11.1.0 (b145ddb). Datom-codec 09a0526 and protos c93b598 stay.

- `Query` is `Input` and `Response` is `Output`, as every Signal names them since ethos-zero 26.0.0; `Contracted` is implemented for `Input`. The file also generates `Answering`, one capability per input, and `Answerable`, whose `type Answer` is `Output`.
- ethos-zero refuses a newtype over a declared struct (`Wrapping`), so the declarations `Unknown.Pane` and `AttemptInProgress.Pane` are gone and `Outcome`'s variant is written `AttemptInProgress.Pane`. `Outcome::Unknown` already carried `Pane`; `Outcome::AttemptInProgress` now carries `Pane` where it carried the newtype `AttemptInProgress(Pane)`. The rkyv archive and the Datom text of every value are unchanged: a newtype archives as its one field and prints as it, so `Listed.AttemptInProgress.{ main wQ:pT }` reads as before.

To deploy: rename `Query` and `Response` to `Input` and `Output`, and write `Outcome::AttemptInProgress(pane)` where it wrapped `AttemptInProgress(pane)`; then repin signal-capsule-nexus 1.0.0 with signal 11.1.0.

## 0.2.0 — signal 10.3.0, datom-codec 0.33.0, protos 0.33.0

Repins signal 10.3.0 (7afb), datom-codec 0.33.0 (eabe) and protos 0.33.0 (3c7a), each spelled as signal spells it so the lock holds one source of each. signal 10.3.0 changes its exchange ledger, not `Contracted`, `Signalizable` or `Restorable`, which this contract uses unchanged.

- The generated contract is regenerated with ethos-zero 19.2.0 (5a5d). The authored `signal.ethos` is unchanged; the generated types add `PartialOrd` and `Ord` (and `Copy` where the scalar is `Copy`). No type, variant or field changes, and the rkyv layout is unchanged.
- protos 0.33.0 prints a balanced guillemet pair inside a string without an escape; a consumer holding datom text with an unbalanced guillemet re-reads it.
- The repository gains a Nix check route: `flake.nix` with build, test, test-datom, doc, fmt and clippy checks, and `rust-toolchain.toml` selecting Rust 1.99.1 by version with that manifest's hash. `tests/datom_contract.rs` reads and prints datom text for the query and response shapes and refuses wrong shapes.

To deploy: repin signal-capsule-nexus 0.2.0 in the consumer and enable `datom` only where text is spoken.
